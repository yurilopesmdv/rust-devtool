# C001 — CI opcional para todo o catálogo web

Status: **concluída localmente; CI remota pendente**

## Entrega e aceite

Ampliar CI gerada para Node/Nest/Rust/Python/Go e frontends existentes, com checks da própria aplicação, versões fixadas, sem deploy/segredos. Verificar projeto isolado, fullstack monorepo e split; none omite YAML e receita registra a escolha. Executar os comandos reais dos projetos e validar workflows com actionlint.

## Implementação e evidência local

Adapters por gerenciador npm/uv/Cargo/Go, com `.ci/check.sh` chamado pelo workflow. Catálogo e wizard habilitam as oito stacks. Monorepo gera dois jobs; split mantém CI nos dois repositórios/receitas. None omite workflow e script. Actions por SHA, permissões de leitura e timeout; nenhum deploy ou serviço é iniciado.

Os scripts reais das oito bases passaram, usando dependências dos locks e runtimes locais preparados. Os 53 workflows das oito bases e 30 combinações fullstack passaram no actionlint 1.7.12. Workspace completo (69 testes Rust, mais fixture ignorada acionada pelo pai), 31 testes Python de manutenção, Ruff, Clippy, PTY e 78 documentos com links válidos. A primeira execução do npm no sandbox bloqueou esbuild com EPERM; a repetição com execução local autorizada passou. A CI deste repo passa a executar os próprios scripts gerados nas matrizes existentes e actionlint em todas as combinações.

Guia de uso e extensão por gerenciador atualizado. Banco/cache/segredos não são provisionados pelo workflow; testes condicionais podem ser pulados sem URLs. Serviços de teste e migrations precisam de configuração explícita. Rust usa o canal stable, não uma versão de compilador fixa.
