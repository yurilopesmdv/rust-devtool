# M001 — Migrations PostgreSQL opcionais

Status: **concluída localmente; CI remota pendente**

## Entrega e aceite

- Opção de receita/CLI para dbmate, permitida somente com PostgreSQL; none omite arquivos e requisitos.
- Binário Linux fixado e verificado por SHA-256, instalação local explícita, sem sudo/global.
- Comandos status/up explícitos, sem executar no startup ou em new.
- Serialização concorrente, ledger de checksums dos arquivos aplicados, falha fechada se houver divergência ou aplicação sem ledger.
- Testes PostgreSQL de falha transacional, repetição, concorrência e alteração indevida; diagnóstico sem URI/segredos.
- Documentação de dependências, instalação, adoção da preparação demonstrativa e recuperação.

## Evidência

Cinco aplicações geradas passaram contra PostgreSQL 17.6 autenticado temporário: status/up repetido, checksum de arquivo alterado, rollback de SQL com falha, correção e retomada, duas execuções concorrentes. Teste também usa caminho com espaços e snapshot privado dos arquivos aplicados. Dbmate v2.37.0 obtido da release oficial e verificado por SHA-256, somente em /tmp para validação.

Workspace completo (fmt/test/Clippy), 31 testes de manutenção, Ruff, actionlint, sintaxe sh e links locais aprovados. Testes de geração cobrem opção ligada/desligada em todas as stacks e opção inválida; flag de banco none desliga migrations herdadas. Um binário com checksum incorreto é recusado sem execução.

A integração usa psql e Python stdlib para manter senha fora de argumentos; libpq não expandiu URI via PGDATABASE no teste, por isso o helper converte os componentes para ambiente. Teste de falha detectou que quit com argumento não propagava erro nessa versão psql; substituído por erro SQL explícito sob ON_ERROR_STOP.

Job generated-migrations implementado, ainda sem run remoto desta alteração. Janela entre commit e registro de checksum documentada com recuperação manual auditada e falha fechada; não há baseline/reset automático ou Job de migrations em clusters.
