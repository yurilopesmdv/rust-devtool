# T011 — Gerar snapshots de locks Rust por comando

Status: **concluída; execução remota aprovada** · Prioridade: **P1**

Dependências: [T005](T005.md)

## Entrega

Criar script que enumera combinações Rust e atualiza snapshots de Cargo.lock.

## Critérios de conclusão

- Ordem e nomes determinísticos; gera em /tmp.
- Modo check detecta diferenças sem sobrescrever snapshots.
- Não usa versões flutuantes para dependências diretas.

## Verificação

Rodar duas vezes e comparar saídas; confirmar --locked nos fixtures.

## Evidência local anterior à execução remota

- Criados update_rust_locks.py e o example rust_lock_manifests, que reutiliza generator/integrations/rust::manifest como única composição de dependências.
- São geradas 12 combinações em diretórios temporários. --check não sobrescreve snapshots; --write publica após resolver todas; --upgrade é explícito e permitido somente com --write.
- Fixadas as quatro versões diretas antes expressas como intervalos, nas versões já resolvidas pelos locks (Tokio 1.54.1, serde_json 1.0.154, tower-http 0.6.11 e tower 0.5.3). Não houve atualização de pacotes.
- Onze snapshots tiveram o bloco do projeto reordenado pelo Cargo. Comparação TOML confirmou igualdade de todo o conteúdo semântico: versões, checksums e dependências preservados.
- Duas execuções --check --offline produziram a mesma saída: 12 combinações, zero diferenças. Todos os fixtures passaram no fetch --locked para o host Linux.
- Quinze testes Python de manutenção passaram, incluindo normalização, modo check sem escrita, escrita idempotente e rejeição de upgrade em modo check. Workspace passou em fmt/59 testes/doctests/Clippy.
- Job rust-lock-snapshots validado com actionlint; a primeira execução remota ainda está pendente. Documentação em ferramentas/boilerplate/docs/locks.md.
