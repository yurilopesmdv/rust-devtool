# T009 — Extrair lifecycle Node para fragmentos legíveis

Status: **concluída** · Prioridade: **P1**

Dependências: [T008](T008.md)

## Entrega

Mover somente os fontes de configuração/startup/shutdown do adapter Node para fragmentos próprios.

## Critérios de conclusão

- Não muda contratos HTTP nem dependências instaladas.
- Omissão de integrações continua comprovada pela matriz.
- Fragments passam em lint/formatação no projeto gerado.

## Verificação

Comparar arquivos efetivos antes/depois e validar Express/Nest com PostgreSQL.

## Evidência

- Extraídos seis fragmentos TypeScript: config-env.ts, config-vault.ts, lifecycle.ts, express-server.ts, nest-lifecycle.module.ts e database-prepare.ts.
- Lifecycle usa slots // @boilerplate:* verificados pelo helper da T008; código completo fica legível fora das strings Rust. O bootstrap stateless permanece no template e o integrado no fragmento próprio.
- As 12 gerações completas comparadas ao baseline permaneceram idênticas byte a byte; dependências e contratos HTTP não mudaram.
- Express/Nest × PostgreSQL/MongoDB e Express/CommonJS × dois bancos passaram em lint/formato/build/testes, persistência e readiness com serviços isolados, encerrados ao final.
- Seis casos sem banco (monitoria apenas, cache apenas e Vault apenas, nas duas stacks) também passaram nos checks. O try sem conexões recebe comentário explícito para manter o lint válido.
- sh scripts/check-workspace.sh --offline passou com 59 testes. As matrizes continuam verificando omissão de módulos desativados.
