# T013 — Atualizar locks npm base e superset

Status: **concluída** · Prioridade: **P1**

Dependências: [T003](T003.md)

## Entrega

Versionar o procedimento de atualização/poda dos locks npm.

## Critérios de conclusão

- Versões de TS/parser compatíveis verificadas sem legacy-peer-deps.
- Não deixa dependências opcionais desativadas no pacote final.
- Modo check não altera fontes; npm ci valida base e adapter.

## Verificação

Gerar Express/Nest com nenhum banco e cada banco; lint/build/test.

## Evidência

- Compositor Node compartilhado pelo gerador e pelo example de manutenção; oito snapshots npm verificados offline sem diferenças e instalados com npm ci, sem legacy-peer-deps.
- Cinco bases ESM e Express CommonJS passaram lint, format, typecheck, build e testes reais. TypeScript e typescript-eslint compatíveis nas versões distribuídas.
- Seis aplicações Express/Nest (PostgreSQL/MongoDB, incluindo CommonJS) passaram persistência/readiness com bancos temporários autenticados; Compose config e Kustomize válidos. Serviços encerrados pelo runner.
- Teste de poda cobre ambos os backends e os três bancos, exigindo ausência de Redis/métricas/drivers desativados. 20 testes de manutenção e check completo do workspace aprovados.
- Uma primeira execução restrita bloqueou o binário esbuild; repetição autorizada fora dessa restrição passou. Nenhuma execução remota foi realizada.
